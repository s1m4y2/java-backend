## 📚 Topics Covered

### Maven

Maven is a build automation and dependency management tool used in Java projects.

It helps with:

- Dependency management
- Project structure
- Build automation
- Testing
- Packaging
- Project lifecycle management

Instead of manually downloading and managing libraries, Maven can download the required dependencies from repositories and manage them for the project.

---

## 📄 pom.xml

`pom.xml` is the main configuration file of a Maven project.

It contains information such as:

- Project identity
- Dependencies
- Version
- Packaging
- Build configuration

Example:

```xml
<groupId>com.simay</groupId>
<artifactId>maven-practice</artifactId>
<version>1.0-SNAPSHOT</version>
<packaging>jar</packaging>
```

---

## 🆔 Maven Coordinates

A Maven project is identified using:

- `groupId`
- `artifactId`
- `version`

**groupId**

Identifies the organization or owner of the project.

```text
com.simay
```

**artifactId**

Identifies the project itself.

```text
maven-practice
```

**version**

Specifies the project version.

```text
1.0-SNAPSHOT
```

Together:

```text
com.simay:maven-practice:1.0-SNAPSHOT
```

---

## 📦 Dependencies

Dependencies are external libraries required by a project.

For example, Java itself does not provide JUnit as part of the standard language.

Maven can download JUnit and make it available to the project through `pom.xml`.

Example:

```xml
<dependency>
    <groupId>junit</groupId>
    <artifactId>junit</artifactId>
    <version>3.8.1</version>
    <scope>test</scope>
</dependency>
```

The dependency is downloaded from a Maven repository and stored in the local Maven repository.

## 📁 Maven Project Structure

A typical Maven project follows this structure:

```text
maven-practice/
│
├── pom.xml
│
├── src/
│   ├── main/
│   │   ├── java/
│   │   └── resources/
│   │
│   └── test/
│       └── java/
│
└── target/
```

**`src/main/java`**

Contains the main Java source code.

**`src/main/resources`**

Contains non-Java resources such as configuration files.

**`src/test/java`**

Contains test code.

**`target`**

Contains Maven build output.

Examples:

- `.class` files
- test results
- `.jar` files

The `target` directory can be regenerated by Maven and should not normally be committed to Git.

## 🔄 Maven Build Lifecycle

Today I practiced the following Maven commands:

- `mvn compile`
- `mvn test`
- `mvn package`
- `mvn install`
- `mvn clean`

### 1. mvn compile

Compiles the Java source code.

```text
.java
  ↓
mvn compile
  ↓
.class
```

The compiled classes were created under:

```text
target/classes/
```

For example:

```text
target/classes/com/simay/App.class
```

### 2. mvn test

Runs the project's tests.

The project contained a JUnit test:

```text
AppTest
```

Result:

```text
Tests run: 1
Failures: 0
Errors: 0
Skipped: 0
```

The build completed successfully.

### 3. mvn package

Packages the project into a JAR file.

```text
source code
    ↓
compile
    ↓
test
    ↓
package
    ↓
JAR
```

The generated artifact was:

```text
target/maven-practice-1.0-SNAPSHOT.jar
```

### 4. mvn install

`install` performs the build and also installs the generated artifact into the local Maven repository.

```text
mvn install
      ↓
compile
      ↓
test
      ↓
package
      ↓
install
      ↓
~/.m2/repository
```

The project was installed under:

```text
~/.m2/repository/com/simay/maven-practice/1.0-SNAPSHOT/
```

### 5. mvn clean

Removes the Maven build output.

Before:

```text
target/
```

After:

```text
mvn clean
```

The `target` directory was removed.

Verified with:

```powershell
Test-Path .\target
```

Result:

```text
False
```

## 🆚 Git vs Maven

Git and Maven solve different problems.

**Git**

Git manages:

- Source code
- Version history
- Commits
- Branches
- Collaboration

**Maven**

Maven manages:

- Dependencies
- Build process
- Tests
- Packaging
- Build lifecycle

```text
Git
→ version control


Maven
→ build & dependency management
```

---

## 🚫 Why target/ Should Not Be Committed

The `target/` directory contains generated build artifacts.

It can be recreated using Maven:

```bash
mvn package
```

Therefore it should normally be ignored by Git.

Example `.gitignore`:

```text
target/
.idea/
*.iml
.classpath
.project
.settings/
```
